## 設計規則

沿用 index.html 現有的 CSS 變數與元件，只新增家長端兩色；不引入新字型或套件。

- **色票：** `--paper` `--leaf-strong` `--sun` `--coral` 等照現有（亮、暗、黑板三套）。新增 `--parent`（亮 #183528／暗 #0B1711）與 `--parent-soft`（#E3EEE6／#1F3328），只用在家長頁頂條與分頁。
- **狀態色：** 等待中＝`--sun-soft` 底＋`--sun-ink` 字；已核准＝`--leaf-soft`＋`--leaf-ink`；被拒絕＝`--coral-soft`＋`--coral-ink`；已取消＝虛框灰字。對比都 ≥ 4.5:1。
- **字型：** 粉圓 Huninn（Google Fonts，OFL），黑板主題照現有用霖鶪文楷；數字 `font-variant-numeric: tabular-nums`。
- **徽章圖：** 銀、金兩種小徽章 SVG（提案裡的 `#medal-s`、`#medal-g`），金屬漸層沿用 index.html `badgeSVG` 的 metal 色（銀 #FFFFFF→#D9DEE4→#8E97A3，金 #FFF3B8→#E9B949→#B07A1E）。枚數一律分開寫「銀 5・金 2」，不加總；圖旁一定寫「銀」「金」字，不只靠顏色分辨。
- **元件：** 主按鈕用現有 `.big`（≥ 58px、按下下沉）；次按鈕 `.iconbtn` 風格 ≥ 44px；卡片用現有 `.card`；不能換的獎項用虛框＋灰字＋一行原因。
- **觸控與版面：** 所有可點元件 ≥ 44×44px；390px 寬不橫向捲動；PIN 數字鍵 60px 高。
- **圖示：** 玩家頭像與導覽沿用 emoji（現有做法），頭像可選 🌱🦊🐢🐳🦄🚀 等 12 個。
- 沒有 3D 場景，不適用 3D 視覺規則。

### 計算規則

- 可用銀＝銀入帳＋銀調整 − Σ 實扣銀（核准＋待核准）；可用金同理；保留中的銀、金＝待核准的實扣銀、實扣金，分開算。實扣在申請時決定：銀付銀價、金付金價；銀不夠而且金可抵銀開著，就用剩下的金補，1 金抵 1 銀；銀不能抵金。實扣寫進兌換列，核准、拒絕、取消都照這筆，不重算。
- 本週已用＝同週鍵、核准＋待核准的筆數。週鍵＝申請時間在台北時區那週週一的日期（如 `2026-11-02`），自己算，不用 `YYYY-ww`。
- 入帳限速：每位玩家每天最多入帳 10 枚（常數 `DAILY_BADGE_CAP`），at 晚於伺服器時間 5 分鐘以上或超過上限的不入帳、標「異常」，家長紀錄分頁看得到。

### Script Properties（不放試算表）

- `PEPPER`：32 位元組亂數，第一次執行 setup 自動產生，不寫進 repo。
- `pin:<邀請碼>` = {salt, h}，h = HMAC-SHA256(salt+PIN, PEPPER)。
- `pinfail:<邀請碼>` = {n, until}；連錯 5 次 until = 現在＋15 分鐘，成功歸零。
- `pinsetup:<邀請碼>` = 一次性設定碼的雜湊；由 `adminIssueSetupCode`（ADMIN\_TOKEN）產生，用過刪除。
- Session：Cache `ps:<SHA256(token)>`，TTL 30 分鐘；token＝兩個 `Utilities.getUuid()` 串接，前端只放記憶體。

### localStorage

新增 `player`、`players-cache`；p1 以外的玩家鍵加前綴（`p2:badges`、`p2:progress-…`、`p2:lib-rec:…`、`p2:g3plants-rec`）。徽章餘額不放 localStorage。

### 後端 action（doPost，沿用 text/plain POST）

| action | 誰能呼叫 | 重點 |
| --- | --- | --- |
| `playerList` `playerSave` | 邀請碼 | 改名、圖示、新增 |
| `playerDisable` `playerRestore` `playerPurge` | session | 停用時待核准改取消；p1 不能 purge |
| `parentStatus` `parentSetPin` `parentLogin` `parentLogout` | 邀請碼（＋設定碼／PIN） | 回傳 `locked` 與剩餘分鐘 |
| `adminIssueSetupCode` `adminResetPin` | ADMIN\_TOKEN | 管理者用 |
| `rewardList` | 邀請碼＋playerId | 附每項銀價、金價、金可抵銀、本週剩餘、是否可換與原因（分顏色寫差幾枚） |
| `rewardSave` | session | 新增／修改／停用 |
| `balance` | 邀請碼＋playerId | 銀、金各自的可用、保留、累計 |
| `redeemRequest {playerId, rewardId, requestId}` | 邀請碼 | 鎖內：requestId 已存在就回原筆 → 檢查啟用、次數，依金可抵銀算實扣銀與實扣金並檢查餘額 → appendRow＋紀錄 → flush |
| `redeemCancel` `myRedeems` | 邀請碼＋playerId | 只能取消自己的待核准 |
| `redeemList` `redeemDecide {id, decision, reason}` | session | 鎖內重讀；不是待核准回 `conflict`（同決定回 ok）；核准前再算餘額 |

## 技術做法

照研究報告做，重點是「先把後端合併與帳本做對，再接畫面」。建議工單順序：

1. 假後端：Node 用 `vm.runInContext` 載入 Code.gs，注入記憶體版 `SpreadsheetApp`、`LockService`、`Utilities`（用 node crypto）、`PropertiesService`、`CacheService` 與可控時鐘，模擬 `doPost({postData:{contents}})`。
2. 玩家：玩家表、`saveBank` 依玩家合併、「徽章」表加玩家ID、前端玩家切換與 localStorage 前綴。
3. 徽章入帳表：`badgeSync`／`saveBank` 合併時寫入新 at、限速與異常標記、第一次同步補入現有 earned。
4. 家長 PIN：PEPPER、設定碼、鎖定、session；前端 `#parent` 路由、數字鍵、自動上鎖（`visibilitychange` 變 hidden 或 3 分鐘沒操作）。
5. 獎勵與兌換後端：`rewardList`／`rewardSave`、`redeemRequest`／`redeemCancel`／`redeemDecide`、週鍵、鎖內重算。
6. 小孩端畫面 2–4；`crypto.randomUUID()` 當 requestId，重送沿用，按鈕在回應前停用。
7. 家長端畫面 5–10。
8. 部署說明與 BUILD\_REPORT。

前端仍是單一 index.html（現有架構），不引入 Vite 或框架；派工範本裡的 Vite 要求不適用這個 repo：改成加一個 \`npm run build\`，把 index.html 與它用到的檔案複製到 dist/，並把 API 網址換成假後端（\`?api=mock\`），讓 dist/index.html 直接開得起來、雲端預覽可測。後端連不到時小孩端只顯示錯誤，不用本機數字冒充。在 Claude 成品沙盒裡偵測到 iframe 就不顯示 Face ID 按鈕。

## 法律與標示

親友家庭也會用，暱稱與兌換紀錄可能算個資；照規劃階段建議：可用代號、告知、可刪除。

- 暱稱欄提示「不要填真名」；不收真名、照片、學校、生日。
- 家長頁放告知文字：存了什麼（暱稱、圖示、徽章數、兌換紀錄）、存在哪（這個家庭的 Google 試算表）、怎麼刪（永久刪除玩家）、PIN 只存雜湊。依據：個資法第 2、8、19、51 條（[全國法規資料庫](https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=I0050021)，查詢日 2026-11-05）；上線前再查一次修法施行日。
- 試算表只分享給管理者自己。公開 repo 不放金鑰、PIN、真實資料；測試全用假後端。
- 沒有新取名，不查商標；沒有第三方素材要署名。

### 部署（使用者自己做）

1. 先複製整份試算表備份。
2. 貼上新的 Code.gs，執行一次 `setup` 補新表與 PEPPER。
3. 「部署 → 管理部署作業」編輯現有部署，版本選「新版本」，網址不變（不要用「新增部署作業」）。
4. 用 `adminIssueSetupCode` 產生每個家庭的設定碼，私下給家長。
5. 先部署後端，再在手機實測後自己合併前端 PR；舊前端不帶 playerId 一律當 p1，可以照常用。
