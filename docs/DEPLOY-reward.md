# 升級家長權限與獎勵

請依序完成以下九步。程式來源是本專案根目錄的 `Code.gs`。

1. **先備份**：打開試算表 → 檔案 → 建立副本。
2. **貼上新程式**：擴充功能 → Apps Script → 打開 `Code.gs` → 全選、貼上 repo 裡新的 `Code.gs` → 儲存。
   這一版調整了停用玩家的檢查順序,要照本文件貼上新的 `Code.gs` 並更新部署,前端才有後端防線。
3. **執行一次 `setup`**：上方函式選單選 `setup` → 執行。會補上「玩家、徽章入帳、獎勵、兌換、兌換紀錄」五個工作表，以及「徽章」表第 5 欄「玩家ID」，並產生 `PEPPER`。在專案設定的指令碼屬性看得到；不要外流、不要刪除，刪了所有 PIN 都會失效。可以重複執行，不會覆蓋資料。
4. **更新部署**：部署 → 管理部署作業 → 鉛筆（編輯）→ 版本選「新版本」→ 部署。網址不變。**不要用「新增部署作業」**，那會產生新網址。
5. **發設定碼**（每個家庭一次）：不必把管理者金鑰拿出來。在 Apps Script 編輯器新增下面這段暫時函式，把邀請碼改成該家庭的，選 `tmpIssue` 執行，到「執行紀錄」看設定碼。**看完把這段函式刪掉、再儲存**，不必重新部署。

   ```js
   function tmpIssue() {
     console.log(adminParent({ action: 'adminIssueSetupCode', family: '這裡填邀請碼' }));
   }
   ```

   設定碼私下交給家長。一個家庭只會有一組有效的，重發會讓舊的失效。
6. **家長設定 PIN**：在手機打開 `網站網址/#parent` → 輸入設定碼與新 PIN。可以把這個網址加到手機主畫面。
7. **手機實測**：用 PR 的前端實測。`npm run build` 後開 `dist/index.html` 是假後端示範；要測真後端，由使用者自行決定。確認沒問題後，**使用者自己按合併 PR**。合併等於上線。舊前端在合併前可以照常用，它不帶玩家資料，一律當第一位玩家。
8. **忘記 PIN 或要重設**：同第 5 步的暫時函式，把 `action` 改成 `adminResetPin`，再發一次設定碼。執行後同樣私下交給家長，刪掉暫時函式並儲存，再由家長依第 6 步設定。
9. **退回**：部署 → 管理部署作業 → 編輯 → 版本選舊版 → 部署；前端未合併就不用動。新工作表留著不影響舊版。

## 上線前再確認

- 個資法修法施行日：上線前再查一次[全國法規資料庫《個人資料保護法》](https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=I0050021)，確認當時的施行狀態。
- 試算表只分享給管理者自己。

## 保溫觸發器

貼上新的 Code.gs 後，在 Apps Script 編輯器選擇 `setup` 並按執行一次。授權時會多要求「管理觸發器」權限，允許即可。重跑 `setup` 不會重複建立保溫觸發器。

觸發器每 10 分鐘執行一次 `keepWarm`，只讀 CacheService 快取，不開啟試算表。Apps Script 免費帳號觸發器每天總執行時間上限為 90 分鐘；以每次約不到 1 秒、一天 144 次估算，遠低於上限。實際執行時間仍依服務狀況而定。

Google 沒有保證此方式能讓網頁應用程式避免冷啟動；保溫是否有效，仍須用之後工單加入的家長頁「連線診斷」實測。
